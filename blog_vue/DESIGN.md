# Design System: xiuxin-blog

## 1. Overview

**Creative North Star: "The Neon Terminal"**

This is a cyber/tech-themed admin interface for blog content management. The design philosophy centers on creating a focused, immersive workspace where the dark gradient background and ambient canvas animations provide atmosphere without distracting from the content-editing task. The interface uses a layered-glass aesthetic: translucent card surfaces with `backdrop-filter: blur`, blue-cyan accents that glow subtly, and micro-interactions that feel tactile and confident.

The system explicitly rejects the AI-default aesthetic: no cream/beige warm-neutral backgrounds, no editorial-serif display heads, no decorative glassmorphism applied wholesale, no tiny uppercase tracked eyebrows above every section, and no hero-metric card grids. This is a functional tool, not a marketing page.

**Key Characteristics:**
- Dark gradient surface (#0a1628 → #1a2a4a) as the foundational canvas
- Layered glass-morphism cards with translucent backgrounds and blur
- Azure-blue (#3b82f6) as the primary accent with cyan (#06d6d3) and orchid-purple (#8b5cf6) as gradient partners
- System-font stack for maximum readability and performance
- Ambient canvas animations (matrix rain, bezier curves) as background atmosphere only
- Responsive down to mobile with layout reflow (sticky sidebars → static stacked)

## 2. Colors: The Neon Terminal Palette

A cyber/tech palette built on deep charcoal void surfaces with luminous blue-cyan accents and purple highlights. The surface never goes pure black — gradients from #0a1628 to #1a2a4a maintain depth. Text is light-on-dark for readability.

### Primary

- **Charcoal Void** (#0a1628): The deepest background color, used as the base of the app-container gradient. On the article page, the even deeper #080b18 is used.
- **Navy Mid** (#1a2a4a): Secondary gradient stop in the app-container background.
- **Navy Deep** (#0d1b2a): Final gradient stop, creates depth in the background.

### Secondary (Accent)

- **Azure Blue** (#3b82f6): The primary brand accent. Used for links, active states, focus glows, borders on interactive elements, and the custom cursor color.
- **Neon Cyan** (#06d6d3): Secondary accent. Appears in button gradients, scroll-progress bar, and the back-to-top button gradient.
- **Orchid Purple** (#8b5cf6): Tertiary accent. Used in button and progress-bar gradients, distortion effects.

### Neutral

- **Surface Dark** (#1e293b): Card/container backgrounds. Used as rgba(30, 41, 59, 0.4) for glass-morphism effect with 40% opacity.
- **Text Primary** (#e2e8f0): Main body text across all surfaces.
- **Text Secondary** (#93c5fd): Subdued text, metadata, labels.
- **Text Muted** (#94a3b8): Placeholder text, secondary information.
- **Text Dim** (#475569): Very dim text for less important information.
- **Accent Blue** (#00ccff): Used in the scroll-progress gradient and back-top button.
- **Error Red** (#ef4444): Error states and destructive actions.

### Named Rules

**The Surface Continuity Rule.** Every surface — cards, inputs, buttons, dialogs — uses the same underlying surface token (rgba(30, 41, 59, 0.4)) with optional border tinting. Never introduce a flat white or light surface; maintain the dark aesthetic consistently.

**The One Voice Rule.** The Azure Blue (#3b82f6) accent is used on ≤30% of any given screen. It carries primary actions, active states, and focus indicators. Its rarity is the point.

## 3. Typography

**Display Font:** None — the project uses a system-font stack with no custom web fonts.
**Body Font:** System UI stack: `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', 'Roboto', 'Oxygen', 'Ubuntu', 'Cantarell', 'Fira Sans', 'Droid Sans', 'Helvetica Neue', sans-serif`
**Label/Mono Font:** Same system stack; no separate mono font is loaded.

**Character:** Technical, functional, and highly readable. No decorative display typography — all hierarchy is conveyed through weight, size, and color. This is a tool interface; typography serves clarity, not aesthetic flourish.

### Hierarchy

- **Heading LG** (700, 3rem / 48px, line-height 1.1): Article page cover titles. Letter-spacing 0.125em. Text-shadow for depth.
- **Heading MD** (600, 1.8rem / 29px, line-height 1.2): Section titles within articles.
- **Heading SM** (600, 1.2rem / 19px, line-height 1.4): Card/section subtitles (e.g., "章节索引", "文章摘要").
- **Heading XS** (700, 1.8rem, line-height 1.2): Login page titles.
- **Body** (400, 1.05rem / 17px, line-height 1.8): Article content, abstract text. Max width 65–75ch.
- **Body SM** (400, 0.9rem / 14px, line-height 1.6): Metadata, labels, footer text.
- **Label** (500, 0.9rem, color #93c5fd): Form field labels.

### Named Rules

**The Functional Type Rule.** No custom web fonts are loaded; the system-font stack ensures maximum performance and readability. All typographic hierarchy is achieved through font-weight, size, and color — not through decorative font pairing.

## 4. Elevation

**Philosophy:** Layered glass. Depth is conveyed through translucent surface layers with `backdrop-filter: blur(10px)`, not through drop shadows. Cards sit at 40% opacity of the surface-dark color (#1e293b), creating a sense of layered depth on the gradient canvas.

### Shadow Vocabulary

- **Glow, ambient** (`radial-gradient(circle, rgba(59, 130, 246, 0.1) 0%, transparent 70%)`): The radial glow behind the app-container, pulsing slowly. Provides ambient atmosphere.
- **Glow, accent** (`box-shadow: 0 0 10px rgba(0, 204, 255, 0.5), 0 0 20px rgba(6, 182, 212, 0.3), 0 0 30px rgba(139, 92, 246, 0.2)`): Applied to the scroll-progress bar and back-to-top button.
- **Card, subtle** (`box-shadow: 0 4px 20px rgba(0, 0, 0, 0.3)`): Applied to article content cards and abstract cards.
- **Focus, inner** (`box-shadow: 0 0 0 3px rgba(59, 130, 246, 0.2), 0 0 20px rgba(59, 130, 246, 0.1)`): Applied to focused form inputs.
- **Button, hover** (`box-shadow: 0 6px 25px rgba(59, 130, 246, 0.4)`): Applied to the primary submit button on hover.

### Named Rules

**The Flat-Glass Rule.** Surfaces are translucent layers, not floating cards. Border-radius of 8–16px is the maximum; shadows are used only for glow effects on interactive elements, not for card elevation.

## 5. Components

### Buttons

- **Shape:** 8px border-radius (16px on login card container). Full pill on back-to-top.
- **Primary:** Linear gradient 135deg from Azure Blue (#3b82f6) through Neon Cyan (#06b6d4) to Orchid Purple (#8b5cf6). White text. Padding: 14px 24px. Box-shadow glow. Hover lifts 2px and intensifies glow. Active presses down.
- **Ghost/Hover:** The button has a `::before` pseudo-element that animates a light sweep from left to right on hover.
- **Secondary / Social:** Social login icons use circular 44px containers with translucent surface backgrounds and colored hover states (GitHub: white, Google: blue #4285F4, Gitee: red #ED4D50).

### Cards / Containers

- **Corner Style:** 12px on article content cards, 16px on login cards.
- **Background:** rgba(30, 41, 59, 0.4) — 40% opacity of #1e293b.
- **Border:** 1px solid rgba(59, 130, 246, 0.15) — subtle blue tint.
- **Shadow:** box-shadow: 0 4px 20px rgba(0, 0, 0, 0.3).
- **Backdrop:** backdrop-filter: blur(10px).
- **Padding:** 32px on article abstract/content cards, 40px on login card.

### Inputs / Fields

- **Style:** Translucent surface (rgba(30, 41, 59, 0.4)), 1px border at rgba(59, 130, 246, 0.3), 8px radius. No outline by default.
- **Focus:** Border shifts to solid Azure Blue (#3b82f6). Inner glow box-shadow: 0 0 0 3px rgba(59, 130, 246, 0.2) + 0 0 20px rgba(59, 130, 246, 0.1).
- **Caret:** Azure Blue (#38BDF8).
- **Placeholder:** rgba(148, 163, 184, 0.5) — subdued gray.
- **Auto-fill:** Custom webkit-autofill styling overrides the default yellow with the dark surface and blue glow.

### Navigation

- **Style:** Horizontal nav bar (daohang component) that is transparent on the homepage and solid on content pages.
- **Typography:** System labels in medium-weight text with blue-tinted color.
- **Hover:** Background shifts to rgba(59, 130, 246, 0.1) with text-to-white transition.
- **Active:** Active item gets a 3px left border in Azure Blue and a stronger background.

### Loading / Empty States

- **Loading:** Full-screen loading message with centered text in text-secondary color.
- **Error:** Centered error message with red-tinted text (rgba(239, 68, 68, 0.8)).
- **Article Index:** Sticky sidebar with section navigation, backdrop-filter cards for the list.

## 6. Do's and Don'ts

### Do:
- **Do** use the charcoal void gradient (#0a1628 → #1a2a4a → #0d1b2a) as the universal background across all pages.
- **Do** use rgba(30, 41, 59, 0.4) with backdrop-filter: blur(10px) for all card/container surfaces to maintain the layered-glass aesthetic.
- **Do** apply the Azure Blue (#3b82f6) accent sparingly — for primary actions, active states, focus indicators, and borders.
- **Do** use the 135deg blue-to-cyan-to-purple gradient on primary buttons and the back-to-top button for visual consistency.
- **Do** respect `@media (prefers-reduced-motion: reduce)` — disable canvas animations and cursor effects, use instant transitions.
- **Do** maintain 65–75ch line length for article content text.
- **Do** reflow the 3-column layout (index / content / sidebar) to 2-column on tablet and 1-column on mobile.
- **Do** use system font stack — no custom web fonts for maximum performance and readability.

### Don't:
- **Don't** use cream/beige/warm-neutral backgrounds (#fdf6f0, #faf7f2, #fffaf5, etc.) — this is a dark cyber/tech theme. The warm-neutral band (OKLCH L 0.84–0.97, C < 0.06) is explicitly rejected.
- **Don't** introduce editorial-serif display fonts (Fraunces, Newsreader, Playfair) or italic display headings — this is a functional tool, not a magazine.
- **Don't** apply glassmorphism decoratively everywhere — only on card and input surfaces that benefit from the layered effect.
- **Don't** use tiny uppercase tracked eyebrows (small all-caps "ABOUT" / "PROCESS" / "PRICING" labels above every section) — they are AI scaffolding, not intentional design.
- **Don't** use border-left-as-accent greater than 1px on cards, list items, or callouts.
- **Don't** pair gradient backgrounds with 1px solid borders + wide drop shadows on the same element (the ghost-card pattern).
- **Don't** round cards above 16px — cards top out at 12–16px; full-pill is only for tags/buttons.
- **Don't** let the cursor-follower or canvas animations interfere with form input or pagination — hide them over `.form-input`, `.form-group`, and `.pagination` elements.
- **Don't** rely on color alone for article status, tag categories, or interactive states — use text labels, icons, or patterns in addition.
- **Don't** animate CSS layout properties — stick to transform, opacity, and backdrop-filter for smooth 60fps motion.
